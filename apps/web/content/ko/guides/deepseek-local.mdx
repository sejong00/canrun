## Ollama deepseek-r1 태그별로 받는 모델

Ollama의 deepseek-r1에는 크기와 버전이 다른 모델이 태그로 묶여 있습니다.

- `deepseek-r1`, `deepseek-r1:latest`, `deepseek-r1:8b`는 모두 DeepSeek R1 0528 Qwen3 8B를 받습니다. 세 태그는 `deepseek-r1:8b-0528-qwen3-q4_K_M`과 같은 파일을 가리킵니다.
- R1 Distill Llama 8B는 `deepseek-r1:8b-llama-distill-q4_K_M`으로 받습니다. 지금의 `:8b`는 이 모델이 아닙니다.
- `deepseek-r1:14b`는 R1 Distill Qwen 14B이고, `14b-qwen-distill-q4_K_M`과 같습니다.
- `deepseek-r1:32b`는 R1 Distill Qwen 32B이고, `32b-qwen-distill-q4_K_M`과 같습니다.
- `deepseek-r1:1.5b`, `:7b`, `:70b`는 CanRun 카탈로그에 없습니다. R1 모델 카드에 따르면 1.5B와 7B는 Qwen2.5-Math를 바탕으로 만들었습니다. 70B의 바탕은 Llama-3.3-70B-Instruct입니다.
- `deepseek-r1:671b`는 원본 DeepSeek-R1이고, 기본 태그는 0528 버전입니다. CanRun은 이 모델을 계산하지 않습니다.

Ollama 페이지에 따르면 0528 업데이트는 8B 증류 모델과 671B 원본 모델에 들어갔습니다. 그래서 `:14b`와 `:32b`는 지금도 1월에 나온 증류 모델입니다.

기본 태그는 모두 Q4_K_M으로, CanRun이 판정 기준으로 쓰는 양자화와 같습니다. 다만 Ollama는 자체 라이브러리 파일을 씁니다. CanRun은 위 표의 ‘GGUF 출처’에 있는 커뮤니티 GGUF로 계산하므로 파일 크기가 조금 다를 수 있습니다. CanRun이 계산에 쓰는 32B 파일은 <Num kind="fileGB" model="deepseek-r1-distill-32b" />입니다.

## 생각하는 과정도 컨텍스트를 채운다

네 모델은 모두 답하기 전에 추론 과정을 먼저 쓰고, CanRun은 이들을 늘 생각하는 모델로 분류합니다. 1월 모델 카드는 모든 답을 `<think>\n`으로 시작하도록 강제하라고 권합니다. R1 시리즈 모델은 생각 과정을 건너뛰는 경향이 있고, 그러면 성능이 떨어질 수 있다는 이유입니다. 0528 카드는 이제 이렇게 강제하지 않아도 된다고 설명합니다.

생각 과정은 내가 보낸 메시지와 같은 컨텍스트에 쌓입니다. 그래서 다른 토큰과 똑같이 KV 캐시를 차지합니다. KV 캐시는 모델이 앞 내용을 다시 계산하지 않도록 담아 두는 메모리입니다. DeepSeek는 R1과 1월 증류 모델을 평가할 때 답 하나의 최대 길이를 32k 토큰으로 잡았습니다. R1-0528과 0528 8B 모델은 64k 토큰으로 잡았습니다.

## Ollama에서 컨텍스트와 KV 캐시 설정하기

<RuntimeFact id="ollama-kv-cache-type" />. Windows에서는 작업 표시줄 아이콘에서 Ollama 앱을 먼저 종료합니다. 그다음 PowerShell에서 아래 명령으로 서버를 띄웁니다. 16k 컨텍스트에 q8_0 KV 캐시를 쓰는 설정입니다.

```powershell
$env:OLLAMA_CONTEXT_LENGTH="16384"; $env:OLLAMA_FLASH_ATTENTION="1"; $env:OLLAMA_KV_CACHE_TYPE="q8_0"; ollama serve
```

RTX 3090에서 32B 증류 모델도 마찬가지입니다<Expect model="deepseek-r1-distill-32b" gpu="rtx-3090" ctx="16384" kv="q8_0" fits="true" mode="full-gpu" />. RTX 3060 12GB에서는 14B 증류 모델도 GPU에 전부 들어가 원활하게 돌아갑니다<Expect model="deepseek-r1-distill-14b" gpu="rtx-3060-12gb" ctx="16384" kv="q8_0" verdict="A" mode="full-gpu" />. 같은 카드에서 f16 그대로 16k를 쓰면 일부가 시스템 RAM으로 넘어갑니다. 그러면 ‘원활’ 기준 바로 아래로 떨어져 겨우 돌아갑니다<Expect model="deepseek-r1-distill-14b" gpu="rtx-3060-12gb" ctx="16384" verdict="B" mode="partial-offload" />.

DeepSeek V4 Flash는 모든 칸이 이론 추정(±30%)입니다<Expect model="deepseek-v4-flash-0731" gpu="apple-m3-ultra" ram="256" fits="true" confidence="theoretical" />. 압축 어텐션과, 층마다 입력을 섞는 하이퍼 커넥션이 하는 연산을 CanRun 속도식이 세지 않기 때문입니다. 지금 llama.cpp 빌드로 잰 공개 결과는 M2 Ultra에서 잰 한 건뿐입니다. 그 결과와 비교하면 CanRun 추정이 실제로 잰 속도보다 4분의 1쯤 높았습니다. 같은 맥에서 8월 빌드로 잰 결과는 빈 컨텍스트에서 30k까지 가는 동안 5분의 1쯤 느려졌지만, CanRun 추정은 거의 그대로입니다. 그래서 긴 컨텍스트 칸은 실제보다 낙관적입니다. 긴 프롬프트를 읽는 속도는 더 크게 떨어집니다. 같은 8월 결과에서 30k 컨텍스트 뒤에 프롬프트를 읽는 속도는 빈 컨텍스트일 때의 4분의 1쯤이었고, CanRun의 프롬프트 처리 추정에는 이 감소가 들어 있지 않습니다. 2026년 8월 이전 빌드는 맥에서 훨씬 느렸습니다.

가장 불확실한 부분은 CanRun이 정책으로 정한 생각 모드 1.5배 기준입니다. 엄격해진 기준선에 바짝 붙은 결과도 여럿 있습니다. RTX 3090과 RTX 4090에서 돌린 32B 증류 모델이 그렇습니다. RTX 5060 Ti 16GB에서 Q4_K_M과 IQ4_XS로 받은 14B 증류 모델도 마찬가지입니다. RTX 4060의 DeepSeek R1 0528 Qwen3 8B도 기준선 가까이에 있습니다. RTX 3090에서 32k·q8_0으로 돌린 32B 증류 모델도 그렇습니다. 이런 결과는 실제 속도가 몇 퍼센트만 달라도 한 단계씩 바뀔 수 있습니다.

표의 값은 다음 조건을 가정합니다. Windows에서 그 카드가 화면 출력도 맡고, 시스템 RAM은 32GB(DDR5-5600 듀얼 채널)입니다. 8k 컨텍스트와 f16 KV 캐시로 모델 하나를 띄우고, 요청은 한 번에 하나만 처리합니다. Ollama 라이브러리 파일은 CanRun이 계산에 쓰는 커뮤니티 GGUF와 크기가 조금 다릅니다. 내 PC에서 실제로 어떻게 올라갔는지는 `ollama ps`로 확인하세요. 원본 R1과 V3, V4-Pro는 CanRun 계산에 들어 있지 않습니다.

생각 모드가 있는 모델에는 속도 기준을 1.5배 엄격하게 적용합니다. 증류 모델 네 개와 DeepSeek V4 Flash가 여기에 해당합니다. 아래 기준표에는 이 내용이 빠져 있으니, 표의 속도에 각각 1.5를 곱해서 보세요.

## 자주 묻는 질문

### 원본 딥시크 R1도 내 PC에서 돌릴 수 있나요?

이 글에 나온 8GB~32GB 그래픽카드로는 어렵습니다. CanRun도 원본 R1은 계산하지 않습니다. 모델 카드에 따르면 원본 R1은 전체 파라미터 671B, 활성 파라미터 37B인 MoE 모델입니다. 전체 파라미터가 32B 증류 모델의 스무 배쯤 됩니다. CanRun이 계산하는 원본 크기 딥시크 모델은 V4 Flash 0731이고, 메모리가 큰 맥이나 시스템 RAM이 많은 PC가 필요합니다. M3 Ultra 256GB인 Mac Studio에는 MXFP4 파일이 GPU에 전부 들어갑니다<Expect model="deepseek-v4-flash-0731" gpu="apple-m3-ultra" ram="256" fits="true" mode="full-gpu" />. RTX 5090에 RAM 128GB라면 전문가 대부분을 RAM에 두는 방식으로 Q2_K 파일이 들어갑니다<Expect model="deepseek-v4-flash-0731" gpu="rtx-5090" ram="128" quant="Q2_K" fits="true" mode="cpu-moe" />. 흔한 가정용 PC로 돌릴 수 있는 것은 작은 증류 모델입니다.

### 증류 모델은 원본 R1과 같은 모델인가요?

아닙니다. 증류 모델은 R1이 생성한 샘플로 Qwen이나 Llama 모델을 파인튜닝한 모델입니다. 구조도 바탕 모델 그대로입니다. 예를 들어 R1 Distill Qwen 32B는 MoE가 아닌 dense 모델이고, 설정 파일의 모델 종류도 qwen2입니다. 모델 카드에는 이 32B 모델이 여러 벤치마크에서 OpenAI-o1-mini보다 낫다고 적혀 있습니다. CanRun은 답의 품질을 재지 않습니다.

### R1 32B 증류 모델에는 어떤 그래픽카드가 필요한가요?

메모리로 보면 8k 컨텍스트의 Q4_K_M은 24GB인 RTX 3090에 전부 들어갑니다<Expect model="deepseek-r1-distill-32b" gpu="rtx-3090" fits="true" mode="full-gpu" />. RTX 5060 Ti 16GB에는 Q2_K만 전부 들어갑니다<Expect model="deepseek-r1-distill-32b" gpu="rtx-5060-ti-16gb" quant="Q2_K" fits="true" mode="full-gpu" />. RTX 3090에서 32k를 쓰려면 KV 캐시를 q4_0으로 둬야 GPU에 전부 들어가고, 그러면 원활하게 돌아갑니다<Expect model="deepseek-r1-distill-32b" gpu="rtx-3090" ctx="32768" kv="q4_0" verdict="A" mode="full-gpu" />. 32GB인 RTX 5090에서는 32k도 f16 그대로 들어가 쾌적하게 돌아갑니다<Expect model="deepseek-r1-distill-32b" gpu="rtx-5090" ctx="32768" verdict="S" mode="full-gpu" />. 카드를 고를 때는 쓰려는 컨텍스트까지 넣어 필요한 메모리를 계산해 보세요.

### Ollama에서 딥시크 R1이 앞 내용을 잊는 것 같은 이유는 무엇인가요?

생각 과정이 Ollama의 기본 컨텍스트를 채웠을 가능성이 큽니다. <RuntimeFact id="ollama-default-ctx" />. 생각 과정이 길면 4k 컨텍스트는 금방 찹니다. `OLLAMA_CONTEXT_LENGTH`로 컨텍스트를 늘리세요. RTX 4060처럼 8GB인 카드라면 16k에 q8_0 KV 캐시를 함께 쓰세요. 그러면 DeepSeek R1 0528 Qwen3 8B가 GPU에 전부 들어가 쾌적하게 돌아갑니다<Expect model="deepseek-r1-0528-qwen3-8b" gpu="rtx-4060" ctx="16384" kv="q8_0" verdict="S" mode="full-gpu" />.

### 딥시크 R1의 생각 과정을 끌 수 있나요?

Ollama에서는 `--think=false`나 `/set nothink`로 끌 수 있습니다. 다만 DeepSeek의 1월 모델 카드는 생각을 건너뛰면 답이 나빠질 수 있다고 경고합니다. `--hidethinking`은 생각 과정을 화면에서 숨길 뿐, 모델은 그대로 생각합니다. CanRun은 생각을 끈 경우에도 생각 모드 기준을 그대로 적용합니다.
