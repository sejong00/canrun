CPU 전용이라고 따로 준비할 프로그램은 없습니다. llama.cpp README에는 x86 CPU의 AVX, AVX2, AVX512, AMX 지원이 적혀 있습니다. LM Studio 시스템 요구 사항에 따르면 x64 Windows PC에는 AVX2를 지원하는 CPU가 필요합니다. ## RAM 대역폭이 속도를 정한다 — DDR4와 DDR5, 듀얼 채널

토큰 하나를 만들 때 CPU는 그 토큰에 쓰는 가중치를 모두 읽습니다. 지금까지의 대화를 담은 KV 캐시도 함께 읽습니다. 메모리 대역폭은 CPU가 RAM에서 1초에 몇 기가바이트를 읽을 수 있는지를 말합니다. 이 값이 클수록 토큰을 빨리 만들 수 있습니다. CanRun은 RAM의 정격 대역폭에 효율 계수를 곱하고, 토큰당 읽는 바이트로 나눠 속도를 추정합니다. CPU에서 dense 모델을 돌릴 때는 정격 대역폭의 절반을 쓴다고 봅니다. 이 계수는 코어 8개 이상인 CPU의 공개 벤치마크 결과에 맞춰 정했습니다.

듀얼 채널 DDR4-3200의 대역폭은 <Num kind="bandwidth" gpu="cpu-ddr4-3200-2ch" />입니다. DDR5-5600은 <Num kind="bandwidth" gpu="cpu-ddr5-5600-2ch" />, DDR5-6000은 <Num kind="bandwidth" gpu="cpu-ddr5-6000-2ch" />입니다. DDR4-3200에서 DDR5-5600으로 가면 대역폭이 4분의 3쯤 늘고, CanRun 추정 속도도 같은 비율로 오릅니다. Llama 3.1 8B는 두 프로필 모두에서 겨우 돌아갑니다<Expect model="llama-3.1-8b" gpu="cpu-ddr4-3200-2ch" verdict="B" /><Expect model="llama-3.1-8b" gpu="cpu-ddr5-5600-2ch" verdict="B" />. 하지만 DDR5 행의 속도 범위가 DDR4 행보다 한참 위에 있습니다. ### 램 모듈 한 개와 두 개

세 프로필은 모두 듀얼 채널을 가정합니다. 일반 데스크톱 CPU는 메모리 채널이 두 개입니다. 예를 들어 인텔 Core Ultra 9 285K 사양 페이지에도 2채널로 나와 있습니다. 커세어의 듀얼 채널 RAM 설명에 따르면, 모듈 하나만 꽂으면 싱글 채널로 동작합니다. 듀얼 채널은 싱글 채널의 두 배 속도라고 설명합니다. 모듈이 하나면 대역폭이 절반이 되고, CanRun 공식으로는 모든 모델의 추정 속도도 절반이 됩니다. 모듈이 하나뿐이라면 같은 모듈을 메인보드 설명서가 알려 주는 슬롯에 하나 더 꽂아 보세요. CanRun 계산으로는 대역폭이 두 배가 됩니다. 반대로 모듈 네 개를 꽂으면 일부 CPU에서는 정격 메모리 속도가 내려갑니다. 이 경우는 ‘<GuideLink slug="moe-cpu-offload" />’ 가이드에서 다룹니다.

### MoE가 불리해지는 경우

토큰마다 KV 캐시도 읽어야 합니다. 활성 부분이 작은 모델일수록 한 번에 읽는 양에서 KV 캐시가 차지하는 몫이 큽니다. f16 KV 캐시로 32k를 쓰면 Qwen3 30B-A3B의 추정 속도는 8k 추정의 절반을 조금 넘습니다. 같은 조건에서 Llama 3.1 8B는 3분의 2쯤으로 내려갑니다. 또 하나의 한계는 RAM 용량이고, 다음 절에서 다룹니다.

## RAM은 얼마나 필요한가

CPU로 돌리면 모델 파일 전체와 KV 캐시가 RAM에 들어가야 합니다. OS와 열어 둔 다른 프로그램도 같은 RAM을 씁니다. CanRun은 이 몫으로 4GB를 빼고, 남은 용량을 양자화 파일과 KV 캐시의 합계와 비교합니다. 넘치는 부분을 보낼 곳은 없습니다. 합계가 들어가지 않으면 그 RAM 용량에서는 돌릴 수 없다고 판정합니다.

- Llama 3.1 8B는 파일이 <Num kind="fileGB" model="llama-3.1-8b" />, 8k KV 캐시가 <Num kind="kvGB" model="llama-3.1-8b" />라서 16GB면 충분합니다<Expect model="llama-3.1-8b" gpu="cpu-ddr5-5600-2ch" ram="16" fits="true" />.
- gpt-oss-20b는 모델 카드에 메모리 16GB 안에서 돌아간다고 나와 있습니다. 하지만 RAM이 16GB인 PC는 OS도 같은 RAM에 올려야 합니다. CanRun 계산으로는 필요한 메모리가 남는 12GB를 조금 넘어서<Expect model="gpt-oss-20b" gpu="cpu-ddr5-5600-2ch" ram="16" fits="false" />, RAM 32GB가 필요합니다<Expect model="gpt-oss-20b" gpu="cpu-ddr5-5600-2ch" ram="32" verdict="B" />.
- Qwen3 30B-A3B는 파일만으로도 16GB에서 남는 용량보다 커서<Expect model="qwen3-30b-a3b-2507" gpu="cpu-ddr5-5600-2ch" ram="16" fits="false" /> 32GB가 필요합니다<Expect model="qwen3-30b-a3b-2507" gpu="cpu-ddr5-5600-2ch" ram="32" fits="true" />.

CanRun에는 8GB 구성이 없습니다. 같은 규칙으로 계산하면 8GB에서는 4GB가 남습니다. Q4_K_M과 8k라면 Llama 3.2 3B는 들어가지만, Llama 3.1 8B는 들어가지 않습니다.

### 코딩 에이전트는 긴 컨텍스트가 필요하다

코딩 에이전트는 채팅보다 훨씬 긴 프롬프트를 보냅니다. Ollama 문서도 에이전트에는 컨텍스트를 64k 이상 주라고 권합니다. CPU에서는 그만큼 RAM과 시간이 더 듭니다. Qwen3 30B-A3B는 64k에서도 32GB에 들어갑니다<Expect model="qwen3-30b-a3b-2507" gpu="cpu-ddr5-5600-2ch" ram="32" ctx="65536" fits="true" />. 하지만 CanRun 추정 속도는 8k 추정의 3분의 1쯤으로 떨어집니다.

에이전트는 턴마다 지시문, 파일, 명령 결과를 먼저 읽고 나서 답을 씁니다. 이 프롬프트 처리 단계는 CanRun이 CPU에서 추정하지 못하는 부분입니다. CPU만으로도 코딩 에이전트를 돌릴 수는 있지만, 턴마다 오래 기다릴 각오를 해야 합니다. 에이전트에 필요한 컨텍스트와 메모리는 따로 정리했습니다. ‘<GuideLink slug="local-coding-agents" />’ 가이드를 보세요.

## 내장 그래픽, 맥, 스트릭스 헤일로

데스크톱·노트북 CPU 대부분에는 내장 그래픽이 들어 있습니다. 마이크로소프트는 작업 관리자의 GPU 메모리 항목을 설명하면서 이렇게 적었습니다. 내장 GPU의 전용 메모리는 그래픽용으로 떼어 둔 시스템 메모리입니다. 내장 GPU와 외장 GPU 모두 공유 시스템 메모리도 쓸 수 있습니다. 결국 내장 그래픽은 CPU와 같은 듀얼 채널 RAM을 읽습니다. CanRun처럼 메모리 대역폭으로 속도를 계산하면, 내장 그래픽으로 돌려도 RAM 대역폭이 정하는 속도보다 빨라지지 않습니다. CanRun에는 일반 내장 그래픽 프로필이 없습니다. 이런 PC는 RAM에 맞는 CPU 프로필을 고르면 됩니다.

그래픽카드 없이도 모델이 빨리 도는 기기는 메모리 버스가 넓습니다. <HubLink gpu="amd-strix-halo" />의 대역폭은 <Num kind="bandwidth" gpu="amd-strix-halo" />입니다. <HubLink gpu="apple-m4-pro" />는 <Num kind="bandwidth" gpu="apple-m4-pro" />입니다. 둘 다 듀얼 채널 DDR5-5600의 세 배쯤입니다. 이 기기들은 GPU가 그 메모리를 쓰기 때문에, CanRun은 GPU 기준으로 판정합니다. ## 이 숫자는 얼마나 확실한가

메모리 수치는 실제 GGUF 파일 크기와 각 모델의 공개 config로 계산합니다. 공식으로 계산한 값이라 오차 범위를 붙이지 않습니다. CPU에서는 파일 전체와 KV 캐시, 시스템 몫 4GB를 셉니다.

속도는 추정치라서 오차 범위와 신뢰 라벨을 함께 붙입니다. CPU 전용 칸은 보정된 추정이고, 오차 범위는 ±20%입니다. NVIDIA·AMD 그래픽카드에 전부 올라가는 dense 모델을 뺀 나머지에 쓰는 범위입니다. CanRun 속도 공식으로 아직 검증하지 않은 층 구조를 쓰는 모델은 이론 추정(±30%)입니다. LFM2.5와 위에서 본 Ling 3.0이 여기에 속합니다. CPU 계수는 코어 8개 이상인 CPU와 데스크톱용 DDR4·DDR5 듀얼 채널을 가정합니다. CanRun은 코어 수를 계산에 넣지 않습니다. 그래서 코어가 적은 CPU는 범위보다 느릴 수 있습니다.

아래는 듀얼 채널 DDR5-5600에서 Qwen3 30B-A3B를 돌린 공개 벤치마크 결과 한 건입니다. hardware-corner.net이 모은 사용자 측정 결과이고, CanRun이 잰 값은 아닙니다. CanRun의 8k 추정 범위와 나란히 보여 줍니다.

<Measured model="qwen3-30b-a3b-2507" gpu="cpu-ddr5-5600-2ch" />

공개 결과는 CanRun 추정 범위보다 높고, CanRun의 4k 추정보다도 높습니다. 이 모델은 CanRun의 CPU 추정이 실제보다 낮게 나왔을 수 있습니다. CanRun 데이터에는 이 결과가 2k 컨텍스트에서 한 번 잰 값으로 들어 있습니다. 출처는 원래의 Qwen3 30B-A3B를 Q4 파일로 돌린 결과를 범위로 적었고, 2507 업데이트와 모델 구조는 같습니다. CPU와 컨텍스트 길이는 밝히지 않았습니다. 그 범위의 가장 낮은 값도 4k 추정보다 높습니다.

CanRun은 CPU 전용 구성의 프롬프트 처리 속도를 추정하지 않습니다. 프롬프트를 읽는 속도는 대역폭이 아니라 연산 성능에 달려 있습니다. 그래서 여기 나온 속도로는 긴 프롬프트나 붙여 넣은 문서를 읽는 시간을 알 수 없습니다. `llama-bench`로 두 가지를 모두 잴 수 있습니다. `-p`가 프롬프트 처리, `-n`이 생성입니다.

모든 수치는 컨텍스트가 8k까지 찬 상태를 가정합니다. KV 캐시는 f16, 모델은 하나, 요청도 한 번에 하나이고, llama.cpp 계열 런타임을 씁니다. 본문에서 말하는 판정은 이 기준입니다. 다른 컨텍스트 길이의 결과는 표에서 확인하세요. 생각 모드가 있는 모델은 속도 기준을 1.5배로 높여 판정하는데, 범례에는 이 배수가 나오지 않습니다. 판정 기준은 다음과 같습니다.

## 자주 묻는 질문

### 그래픽카드 없이 로컬 LLM을 돌릴 수 있나요?

네. llama.cpp, LM Studio, Ollama 모두 CPU와 시스템 RAM으로 모델을 돌립니다. Llama 3.1 8B Q4_K_M은 RAM 16GB에 들어갑니다. 듀얼 채널 DDR5-5600에서는 겨우 돌아갑니다(보정된 추정)<Expect model="llama-3.1-8b" gpu="cpu-ddr5-5600-2ch" verdict="B" confidence="calibrated" />. CanRun은 CPU 전용 구성에 이보다 높은 판정을 주지 않습니다. MoE 모델인 gpt-oss-20b는 추정 속도가 Llama 3.1 8B보다 높지만, RAM 32GB가 필요합니다<Expect model="gpt-oss-20b" gpu="cpu-ddr5-5600-2ch" ram="32" fits="true" />.

### CPU로 돌리려면 RAM이 얼마나 필요한가요?

모델 파일과 KV 캐시가 들어가고, 시스템 몫 4GB가 남아야 합니다. 8k 기준으로 16GB면 Llama 3.1 8B와 Qwen3 14B Q4_K_M이 들어갑니다<Expect model="llama-3.1-8b" gpu="cpu-ddr5-5600-2ch" ram="16" fits="true" /><Expect model="qwen3-14b" gpu="cpu-ddr5-5600-2ch" ram="16" fits="true" />. 32GB면 gpt-oss-20b와 Qwen3 30B-A3B가 들어갑니다<Expect model="gpt-oss-20b" gpu="cpu-ddr5-5600-2ch" ram="32" fits="true" /><Expect model="qwen3-30b-a3b-2507" gpu="cpu-ddr5-5600-2ch" ram="32" fits="true" />. gpt-oss-120b는 96GB가 필요합니다<Expect model="gpt-oss-120b" gpu="cpu-ddr5-5600-2ch" ram="96" fits="true" />. 컨텍스트를 늘리면 KV 캐시가 커지는데, 얼마나 커지는지는 위 컨텍스트 표에서 볼 수 있습니다.

### CPU 코어가 많으면 더 빨라지나요?

CanRun 계산에서는 코어가 8개쯤 있으면 더 늘려도 생성 속도가 달라지지 않습니다. 생성 속도는 RAM 대역폭이 정하기 때문입니다. 코어가 이보다 적으면 범위보다 느릴 수 있고, llama.cpp에서는 `-t`로 스레드 수를 정합니다. 프롬프트를 읽는 단계는 연산 성능에 달려 있어서 CPU 성능이 더 중요합니다. CanRun은 CPU에서는 이 단계를 추정하지 않습니다.

### DDR4 RAM으로도 되나요?

작은 모델이라면 됩니다. CanRun 계산으로 DDR4-3200은 DDR5-5600 속도의 절반을 조금 넘습니다. DDR5-5600에서는 겨우 돌아갑니다<Expect model="qwen3-14b" gpu="cpu-ddr5-5600-2ch" verdict="B" />. CanRun의 DDR4 프로필은 64GB까지라서 gpt-oss-120b가 들어가지 않습니다<Expect model="gpt-oss-120b" gpu="cpu-ddr4-3200-2ch" fits="false" />. DDR4 PC에 RAM이 96GB 이상이라면 같은 RAM 규칙으로는 들어가지만, CanRun은 그 용량을 계산하지 않습니다.

### CPU에는 어떤 모델이 어울리나요?

RAM에 들어간다면 활성 부분이 작은 MoE 모델이 어울립니다. 32GB라면 gpt-oss-20b와 Qwen3 30B-A3B의 추정 속도가 Llama 3.1 8B보다 높습니다<Expect model="qwen3-30b-a3b-2507" gpu="cpu-ddr5-5600-2ch" ram="32" verdict="B" />. 16GB라면 Kanana 1.5 15.7B-A3B가 들어갑니다<Expect model="kanana-1.5-15.7b-a3b" gpu="cpu-ddr5-5600-2ch" ram="16" fits="true" />.
