## MoE 모델은 dense 모델과 무엇이 다른가

<HubLink model="qwen3-32b" /> 같은 dense 모델은 토큰마다 모든 가중치를 거칩니다. 그래서 생성 속도가 파일 전체 크기를 따라갑니다. MoE 모델은 각 층의 대부분을 ‘전문가’라는 작은 블록 여러 개로 나눠 둡니다. 그리고 라우터가 토큰마다 그중 몇 개만 골라 계산합니다. 설정 파일(config)을 보면 gpt-oss-120b는 층마다 전문가 128개 가운데 4개를 씁니다. ## 전문가를 시스템 RAM에 두는 방법

llama.cpp는 Ollama 0.30 이후 버전을 비롯해 여러 로컬 도구가 쓰는 엔진입니다. llama.cpp에는 이런 배치를 만드는 옵션이 두 가지 있습니다. `--cpu-moe`는 MoE 가중치를 모두 시스템 RAM에 둡니다. `--n-cpu-moe N`은 앞쪽 N개 층의 전문가만 RAM에 두고, 나머지 층의 전문가는 GPU에 남깁니다. b7410(2025년 12월) 이후 빌드는 옵션을 주지 않아도 이렇게 나눠 올립니다. 기본으로 켜진 `--fit` 옵션이 공유 가중치(PR에서는 ‘dense 가중치’)를 먼저 GPU에 두기 때문입니다. 전문가는 VRAM이 모자라는 만큼만 RAM으로 옮깁니다.

CanRun 계산도 같은 순서를 따릅니다. 공유 가중치와 KV 캐시, 연산 버퍼(런타임이 계산 중에 쓰는 메모리)를 먼저 GPU에 둡니다. 남은 VRAM에는 전문가를 층 단위로 채우되, 한 층 분량은 여유로 비워 둡니다. 나머지 층의 전문가는 시스템 RAM에 둡니다. 전문가와 공유 가중치의 크기는 공식으로 어림하지 않고 GGUF 파일 헤더에서 읽습니다. 이렇게 정해진 N이 CanRun 조합 페이지의 llama.cpp 명령에 들어갑니다.

RTX 3060 12GB에서 Qwen3.6 35B-A3B를 돌리면 메모리가 이렇게 나뉩니다. 8k에서 <Num kind="needGB" model="qwen3.6-35b-a3b" />가 필요한데, 카드의 사용 가능 메모리는 <Num kind="usableGB" gpu="rtx-3060-12gb" />입니다. 아래 GPU 막대는 여유로 비운 한 층만 빼고 가득 찹니다. 남은 전문가는 시스템 RAM 막대에 들어갑니다. CanRun은 RAM 4GB를 Windows와 다른 프로그램 몫으로 빼 둡니다. 그래서 RAM이 32GB인 PC는 28GB를 쓸 수 있다고 봅니다.

## RAM 속도가 생성 속도를 정한다

이 배치에서는 토큰 하나를 만들 때 두 곳에서 읽습니다. RAM에 둔 층에서 고른 전문가는 RAM에서 읽습니다. GPU에 둔 전문가와 공유 가중치, KV 캐시는 VRAM에서 읽습니다. 그런데 RAM은 훨씬 느립니다. 듀얼 채널 DDR5-5600의 대역폭은 <Num kind="bandwidth" gpu="cpu-ddr5-5600-2ch" />입니다. RTX 3060 12GB의 VRAM은 <Num kind="bandwidth" gpu="rtx-3060-12gb" />입니다. CanRun 공식은 이 부분에서 RAM 대역폭의 절반만 쓸 수 있다고 봅니다. 이 비율은 공개 벤치마크 결과에 맞춰 정했습니다. 전문가를 RAM에 많이 둘수록 RAM 속도가 생성 속도를 좌우합니다.

대역폭은 전송 속도에 채널당 8바이트와 채널 수를 곱한 값입니다. 듀얼 채널 DDR4-3200은 <Num kind="bandwidth" gpu="cpu-ddr4-3200-2ch" />로, DDR5-5600의 절반을 조금 넘습니다. CanRun 계산으로는 gpt-oss-120b를 돌리는 PC의 RAM을 DDR4-3200으로 바꾸면 추정 속도가 3분의 1에서 5분의 2쯤 떨어집니다. 전문가 대부분을 RAM에 두는 12~32GB 카드에서 그렇습니다. RTX 3060 12GB에서 Qwen3.6 35B-A3B는 GPU에서 하는 일이 더 많아서 5분의 1쯤 떨어집니다. 계산기의 ‘RAM 종류’에서 DDR4-3200·DDR5-5600·DDR5-6000 가운데 내 PC의 RAM을 고르면 직접 확인할 수 있습니다.

일반 데스크톱 CPU는 메모리 채널이 두 개입니다. 인텔 Core Ultra 9 285K와 AMD Ryzen 7 9700X의 사양 페이지에도 2채널로 나와 있습니다. RAM 모듈을 더 꽂으면 용량은 늘지만 채널은 늘지 않습니다. 오히려 정격 속도가 낮아질 수 있습니다. AMD 사양 페이지를 보면 Ryzen 7 9700X의 최대 메모리 속도는 모듈 두 개일 때 DDR5-5600입니다. 네 개를 꽂으면 DDR5-3600으로 내려갑니다. DDR5-3600이면 대역폭이 3분의 2쯤으로 줄어듭니다. 큰 MoE 모델 때문에 RAM을 늘린다면, 모듈 네 개에서 CPU와 메인보드가 지원하는 속도부터 확인하세요.

## 실행 명령 — llama.cpp와 Ollama

Windows용 llama.cpp는 GitHub 릴리스 페이지에서 바로 받을 수 있습니다. NVIDIA 카드라면 CUDA 빌드와, 버전이 맞는 cudart 파일을 함께 받으세요. 두 파일을 한 폴더에 풀고, 그 폴더에서 PowerShell을 열어 아래처럼 `.\llama-server.exe`로 실행합니다. macOS·Linux에서는 `.\llama-server.exe` 대신 `llama-server`라고 씁니다. 2025년 12월 이후 빌드라면 배치를 `--fit`에 맡기는 명령이 가장 간단합니다.

```powershell
.\llama-server.exe -hf ggml-org/gpt-oss-120b-GGUF:MXFP4 -c 8192
```

배치를 직접 정하려면 `-ngl`과 `--n-cpu-moe`를 지정합니다. 직접 지정한 옵션은 `--fit`이 바꾸지 않습니다. 아래는 RTX 3060 12GB와 RAM 64GB로 gpt-oss-120b를 돌리는 명령입니다. CanRun 조합 페이지에 나오는 명령과 같습니다. 다른 카드에 맞는 N은 각 조합 페이지에 있습니다.

```powershell
.\llama-server.exe -hf ggml-org/gpt-oss-120b-GGUF:MXFP4 -c 8192 -ngl all --n-cpu-moe 32 -fa on
```

`-ngl all`은 모든 층을 GPU에 올립니다. 그다음 `--n-cpu-moe 32`가 앞쪽 32개 층의 전문가를 시스템 RAM으로 돌려보냅니다. 컨텍스트를 늘린 뒤 VRAM이 모자라 불러오지 못하면 N을 1~2 올리세요. 하나 올릴 때마다 한 층의 전문가가 RAM으로 더 옮겨 갑니다.

Ollama를 쓴다면 작업 표시줄 아이콘에서 Ollama 앱을 먼저 종료합니다. 그다음 원하는 컨텍스트로 서버를 띄웁니다. PowerShell 창을 하나 더 열어 Hugging Face의 모델을 실행합니다.

```powershell
$env:OLLAMA_CONTEXT_LENGTH="8192"; ollama serve
```

```powershell
ollama run hf.co/ggml-org/gpt-oss-120b-GGUF:MXFP4
```

macOS·Linux에서는 첫 줄을 `OLLAMA_CONTEXT_LENGTH=8192 ollama serve`로 씁니다. GPU와 RAM에 나눠 올리는 방식은 Ollama가 스스로 정합니다. `num_gpu`를 정하지 않으면 Ollama는 GPU 층 수 없이 llama-server를 띄우고, 배치는 llama.cpp의 `--fit`이 맡습니다. 컨텍스트를 계속 같은 값으로 쓰는 설정은 ‘<GuideLink slug="ollama-context-length" />’ 가이드에 있습니다. LM Studio에서는 모델을 불러올 때 ‘Force Model Expert Weights onto CPU’를 켜면 전문가 가중치를 모두 RAM에 둡니다. `--cpu-moe`와 같은 방식입니다.

### 실제로 어떻게 올라갔는지 확인하기

모델을 띄운 상태에서 `ollama ps`를 실행하세요. PROCESSOR 열에 CPU와 GPU에 나눠 올린 비율이 나옵니다. llama.cpp라면 시작할 때 나오는 로그에서 장치마다 올라간 양을 볼 수 있습니다. 전문가 일부를 RAM에 두는 모델은 늘 CPU와 GPU에 나뉘어 나옵니다. 중요한 것은 VRAM에 들어갈 만큼 GPU에 올라갔는지입니다.

Windows에서는 VRAM이 모자랄 때 NVIDIA 드라이버가 공유 시스템 메모리를 빌려 쓸 수 있습니다. 그래서 N을 너무 작게 잡으면 llama.cpp가 오류 없이 추정보다 훨씬 느리게 돌 수 있습니다. NVIDIA 지원 문서에 이 동작을 프로그램별로 끄는 방법이 나와 있습니다. NVIDIA 제어판에서 ‘3D 설정 관리’의 ‘프로그램 설정’ 탭을 열고 llama-server.exe를 추가하세요. 그다음 ‘CUDA - Sysmem Fallback Policy’를 ‘Prefer No Sysmem Fallback’으로 바꿉니다. 그러면 배치가 빠듯할 때 메모리 부족 오류가 나서 바로 알 수 있습니다.

## 이 숫자는 얼마나 확실한가

메모리에 들어가는지는 공식으로 계산한 값입니다. CanRun은 MoE 파일마다 전문가와 공유 가중치의 크기를 GGUF 헤더에서 읽습니다. 여기에 KV 캐시와 연산 버퍼를 더해, PC에서 쓸 수 있는 VRAM·시스템 RAM과 비교합니다. 그래서 RAM 몇 GB부터 들어가는지는 추정이 아니라 계산 결과입니다. 다만 8GB 카드의 gpt-oss-120b처럼 RAM 계단 바로 근처의 결과는 CanRun이 남겨 두는 여유에 달려 있습니다. 시스템 몫 RAM 4GB와 VRAM 한 층 분량입니다.

이 글의 속도는 모두 생성 속도입니다. 전문가를 시스템 RAM에 두는 구성의 속도는 이론 추정(±30%)입니다. 공개 벤치마크 42건과 비교하면 평균 오차는 약 11%였습니다. NVIDIA 카드 35건만 보면 평균 오차가 약 10%이고, 89%가 ±20% 안에 들었습니다. 그래도 운영체제·백엔드·RAM 구성에 따라 40% 가까이 벗어난 경우가 있어 이론 추정 라벨을 유지합니다. 공식이 잘 맞지 않는 구성은 이 비교에서 뺐습니다. Vulkan 백엔드, 8채널 서버 메모리, 32k 이상의 아주 긴 컨텍스트가 그렇습니다.

표의 값은 다음 조건을 가정합니다. Windows에서 그 카드가 화면 출력도 맡고, RAM은 듀얼 채널 DDR5-5600입니다. 8k 컨텍스트와 f16 KV 캐시로 모델 하나를 띄우고, 요청은 한 번에 하나만 처리합니다. llama.cpp의 자동 배치는 GPU마다 VRAM 여유를 따로 남깁니다. 그래서 llama.cpp가 고르는 N은 CanRun 계산과 한 층 정도 다를 수 있습니다.

생각 모드가 있는 모델에는 속도 기준을 1.5배 엄격하게 적용합니다. 생각 모드를 켜면 답 하나에 토큰을 훨씬 많이 쓰기 때문입니다. 이 글의 모델 가운데 gpt-oss-20b와 gpt-oss-120b는 늘 생각합니다. Qwen3.6 35B-A3B와 Qwen3.5 122B-A10B는 생각 모드가 기본으로 켜져 있습니다. Solar Open 100B와 Qwen3 32B도 마찬가지입니다. Gemma 4 26B-A4B는 생각 모드가 있지만 기본으로 꺼져 있습니다. Qwen3 30B-A3B (2507)에는 생각 모드가 없습니다. 아래 기준표에는 이 내용이 빠져 있으니 참고하세요.

모델이 아예 들어가지 않는다면 RAM부터 늘리세요. 들어간 뒤에는 RAM을 더 늘려도 CanRun 추정 속도는 오르지 않습니다. 그다음부터는 VRAM이 크면 GPU에 전문가 층을 더 많이 둘 수 있고, RAM이 빠르면 나머지를 빨리 읽습니다. 카드별 결과는 위 표에 있습니다. RAM을 새로 산다면 모델이 들어가는 가장 작은 용량을 목표로 하세요. 모듈 개수는 CPU가 제 속도를 내는 구성으로 고르세요.

### MoE 모델이 메모리에 들어가는데도 느린 이유는 무엇인가요?

대개 필요 이상으로 많은 부분이 시스템 RAM에 있거나, RAM이 생각보다 느리기 때문입니다. 먼저 `ollama ps`나 llama.cpp 로그로 배치를 확인하세요. Ollama의 GPU 몫이 VRAM보다 한참 적다면 남아 있는 `num_gpu` 설정을 찾아보거나, llama.cpp에서 `--n-cpu-moe`로 직접 나눠 보세요. `--cpu-moe`를 쓰면 VRAM에 자리가 있어도 전문가를 모두 RAM에 둡니다. RAM 모듈을 네 개 꽂으면 두 개일 때보다 정격 속도가 낮을 수 있습니다. 컨텍스트가 길어도 전문가가 RAM으로 더 옮겨 갑니다. Windows에서는 배치가 빠듯하면 공유 GPU 메모리로 넘칠 수 있습니다. 이 내용은 실행 명령 절에서 설명했습니다.

### `--cpu-moe`와 `--n-cpu-moe` 중 무엇을 써야 하나요?

배치를 직접 정한다면 `--n-cpu-moe N`을 쓰세요. 들어가는 만큼 전문가 층을 GPU에 남기기 때문입니다. `--cpu-moe`는 모든 층의 전문가를 RAM에 두는 것과 같습니다. 카드에 전문가를 둘 자리가 있다면 그만큼 느려집니다. 2025년 12월 이후 llama.cpp 빌드라면 둘 다 빼고 `--fit`에 맡겨도 됩니다. 다만 `-c`는 남기세요. 빼면 `--fit`이 가중치를 옮기기 전에 컨텍스트부터 줄일 수 있습니다. CanRun 조합 페이지에는 카드마다 계산한 N이 들어 있습니다.
