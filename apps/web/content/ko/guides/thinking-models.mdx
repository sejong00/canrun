## 생각 모드가 있는 모델 — 늘 켜짐·기본 켜짐·기본 꺼짐

요즘 오픈 모델은 답하기 전에 추론 과정을 먼저 쓰는 경우가 많습니다. 런타임은 이 부분을 답과 따로 보여 줍니다. Ollama 명령줄에서는 `Thinking...`과 `...done thinking.` 사이에 나옵니다. CanRun은 카탈로그의 모델마다 생각 모드가 있는지, 어떻게 켜고 끄는지를 기록해 둡니다. 근거는 모델 카드와 채팅 템플릿입니다. 채팅 템플릿은 대화를 모델이 읽는 프롬프트 형식으로 바꿔 주는 파일입니다. 모델은 다섯 갈래로 나뉩니다.

- **늘 생각함**: gpt-oss-20b·gpt-oss-120b와 DeepSeek R1 distill 모델(Qwen 32B·Llama 8B)입니다. gpt-oss는 추론 강도를 low·medium·high 중에서 고를 수 있지만, 끄는 설정은 없습니다. 따로 정하지 않으면 채팅 템플릿이 medium을 씁니다. DeepSeek R1 distill 모델 카드는 오히려 답을 늘 `<think>` 태그로 시작하게 하라고 권합니다. 모델이 생각을 건너뛰면 답이 나빠지기 때문입니다.
- **기본으로 켜짐, 끌 수 있음**: Qwen3 8B·14B·32B, Qwen3.5·Qwen3.6·Qwen3.8 계열, EXAONE 4.5 33B 등입니다.
- **기본으로 꺼짐, 켤 수 있음**: Gemma 4 계열과 EXAONE 4.0 32B입니다. Gemma 4는 시스템 프롬프트 맨 앞에 `<|think|>` 토큰이 있을 때 생각합니다. EXAONE 4.0은 템플릿에 `enable_thinking=True`가 들어가야 생각합니다.
- **모델이 스스로 정함**: HyperCLOVA X SEED Think 14B입니다. 모델 카드에 따르면 기본 설정에서는 추론할지 바로 답할지를 모델이 정합니다. CanRun 카탈로그는 MiniCPM5 모델도 이 갈래로 분류합니다.
- **생각 모드 없음**: Llama 3.1 8B, Gemma 3, Phi-4, Qwen3 30B-A3B (2507)입니다. Qwen3 30B-A3B (2507)은 Instruct-2507 판입니다. 모델 카드에 비생각 모드만 지원한다고 적혀 있습니다. Phi-4는 카탈로그에서 추론(reasoning) 용도로 분류돼 있습니다. 하지만 모델 카드의 대화 형식에는 생각 블록이 없습니다. 용도 분류와 생각 모드는 별개입니다.

생각 모드는 메모리에 영향을 주지 않습니다. 가중치와 토큰당 KV 캐시는 생각을 하든 안 하든 같습니다. 그래서 GPU에 들어가는지는 모델과 양자화, 컨텍스트로만 정해집니다. 8k에서 Qwen3 14B는 <Num kind="needGB" model="qwen3-14b" />, 생각 모드가 없는 Phi-4는 <Num kind="needGB" model="phi-4" />가 필요합니다. 32B급에서는 Qwen3 32B가 <Num kind="needGB" model="qwen3-32b" />, DeepSeek R1 Distill Qwen 32B가 <Num kind="needGB" model="deepseek-r1-distill-32b" />입니다. 모델 카드에 따르면 이 DeepSeek 모델은 Qwen2.5 32B를 바탕으로 만들었습니다. 생각 모드가 더 쓰는 것은 시간과 컨텍스트입니다. 컨텍스트 이야기는 아래에서 따로 다룹니다.

## CanRun 판정이 1.5배 엄격한 이유

CanRun은 추정 생성 속도를 정해진 기준과 비교해 판정합니다. 기준표는 이 글 끝부분에 있습니다. 이 기준은 모델이 쓰는 토큰 대부분이 사용자가 읽을 답이라고 가정합니다. 생각 모드 모델은 추론을 먼저 쓰고, 답은 추론이 끝나야 시작합니다. 토큰 하나를 만드는 속도는 똑같습니다. 답보다 세 배 긴 추론을 쓰면 응답 전체에 네 배의 시간이 걸립니다. 그중 4분의 3은 답의 첫 글자가 나오기 전에 지나갑니다.

얼마나 오래 생각할지는 질문과 모델, gpt-oss의 추론 강도 같은 설정에 따라 다릅니다. CanRun에는 이를 예측할 데이터가 없습니다. 그래서 토큰 수를 짐작하는 대신, 생각 모드가 있는 모델에는 속도 기준을 모두 1.5배로 올려 적용합니다. ‘쾌적’과 ‘원활’ 기준, ‘불가’ 하한이 모두 기준표 속도의 1.5배가 됩니다. 이 배수는 잰 값이 아니라 엔진 명세에 정해 둔 정책입니다.

기본으로 꺼진 모델에도 이 규칙을 적용합니다. 많이 쓰는 로컬 런타임 두 가지가 생각 모드를 기본으로 켜기 때문입니다. Ollama 소스를 보면, 생각 모드를 켜고 끌 수 있는 로컬 모델은 요청에 `think`가 없을 때 켜진 채로 돌아갑니다. Ollama 테스트 코드에도 Gemma 4가 그런 모델로 나옵니다. llama-server도 채팅 템플릿이 지원하면 생각 모드를 켭니다. `--reasoning off`로 띄울 때만 꺼집니다.

## 생각 모드 끄는 법 — Ollama·llama.cpp·모델별 방식

### Ollama

PowerShell이나 다른 터미널에서 `ollama run`에 `--think=false`를 붙입니다. 대화 중에는 `/set nothink`를 입력하면 꺼지고, `/set think`로 다시 켭니다.

```shell
ollama run qwen3:14b --think=false
```

`--hidethinking`은 다른 옵션입니다. 터미널에 추론을 보여 주지 않을 뿐, 모델은 그대로 생각합니다. 그래서 답을 받기까지 걸리는 시간은 줄지 않습니다.

API로 쓸 때는 `/api/chat`이나 `/api/generate` 요청 본문에 `think`를 넣습니다. Ollama 문서에 따르면 `false`는 모델이 허용할 때 생각을 끄고, `true`는 켭니다. 문자열을 넣으면 단계를 정해 둔 모델에서 그 단계를 고릅니다.

```json
{
  "model": "qwen3:14b",
  "messages": [{ "role": "user", "content": "이 문단을 두 줄로 요약해 줘" }],
  "think": false
}
```

`think`를 빼면 모델의 기본값을 씁니다. `ollama show qwen3:14b`를 실행하면 Capabilities에 thinking이 나옵니다. 단계를 알려 주는 모델이면 고를 수 있는 값과 기본값도 함께 나옵니다. 그래도 기본값에 기대지 말고 `think`를 직접 정하는 편이 낫습니다. 생각 모드를 켜고 끌 수 있는 로컬 모델은, 요청에 따로 적지 않으면 Ollama가 켜 두기 때문입니다. Gemma 4도 마찬가지입니다.

gpt-oss는 Ollama에서도 끄는 값이 없습니다. Ollama가 gpt-oss에 허용하는 값은 `low`·`medium`·`high`뿐이고, 기본값은 medium입니다. 추론을 줄이려면 `ollama run gpt-oss:20b --think=low`로 실행합니다. API라면 `"think": "low"`를 보냅니다.

### llama.cpp

llama.cpp의 서버인 llama-server에는 2026년 3월부터 생각 모드를 끄는 옵션이 따로 있습니다. `--reasoning off`(줄여서 `-rea off`)는 채팅 템플릿에 `enable_thinking=false`를 넘깁니다. Qwen3·Qwen3.5·Qwen3.6·Gemma 4·EXAONE 4.0 템플릿이 읽는 값입니다. 기본값인 `auto`에서는 템플릿이 지원하면 생각 모드를 켭니다. 그 전 빌드에서는 `--reasoning-budget 0`이 끄는 옵션이었습니다. 생각 모드를 끄고 서버를 띄우는 명령은 이렇습니다.

```shell
llama-server -hf unsloth/Qwen3-14B-GGUF:Q4_K_M -c 8192 -ngl all -fa on --reasoning off
```

요청 하나에만 적용하려면 서버 README에 나온 방법을 씁니다. `"reasoning_effort": "none"`을 넣거나, 아래처럼 템플릿 인자를 보냅니다.

```json
{
  "messages": [{ "role": "user", "content": "이 문단을 두 줄로 요약해 줘" }],
  "chat_template_kwargs": { "enable_thinking": false }
}
```

gpt-oss에는 `--reasoning-effort low`를 씁니다. 이 값은 채팅 템플릿으로 넘어가고, 따로 주지 않으면 템플릿은 medium을 씁니다. 끄지 않고 길이만 제한하려면 `--reasoning-budget N`을 씁니다. 추론이 N토큰에 이르면 끝내고, 기본값 `-1`은 제한이 없다는 뜻입니다. `--reasoning-budget-message`는 예산을 다 썼을 때 생각 종료 태그 앞에 넣을 안내 문장을 정합니다.

### 모델 자체의 스위치

- **Qwen3 8B·14B·32B**: 사용자 메시지나 시스템 메시지 끝에 `/no_think`나 `/think`를 붙이면 턴마다 바뀝니다. 템플릿 스위치가 켜져 있을 때만 통합니다. `/no_think`를 써도 답에는 빈 생각 블록이 남습니다. `enable_thinking=False`는 완전히 끄는 스위치이고, 이때는 두 태그가 아무 효과가 없습니다.
- **Qwen3.5·Qwen3.6**: 모델 카드에 따르면 이 태그를 공식 지원하지 않습니다. 런타임 스위치를 쓰세요.
- **Gemma 4**: 시스템 프롬프트가 `<|think|>`로 시작할 때만 생각합니다. Ollama의 Gemma 4 렌더러는 생각 모드가 켜져 있으면 이 토큰을 넣습니다. 결국 런타임 스위치가 정합니다.
- **EXAONE 4.0**: 템플릿에 `enable_thinking=True`가 들어가면 추론하고, 아니면 바로 답합니다.
- **HyperCLOVA X SEED Think 14B**: 템플릿 인자 `force_reasoning`이나 `skip_reasoning`으로 정합니다. 메시지에 적어 넣는 대략적인 길이 제한도 모델 카드에 나옵니다.
- **gpt-oss**: 시스템 프롬프트의 `Reasoning: low` 같은 줄에서 추론 강도를 읽습니다. Ollama와 llama.cpp는 위 옵션으로 이 줄을 대신 써 넣습니다.
- **DeepSeek R1 distill 모델**: 끄는 스위치가 없습니다.

## 생각 토큰도 컨텍스트를 쓴다

지금 쓰는 답의 추론은 사용자 메시지와 같은 컨텍스트에 쌓입니다. 생각 토큰도 다른 토큰처럼 KV 캐시를 차지합니다. KV 캐시는 컨텍스트를 담아 두는 메모리입니다. 모델 카드들은 긴 추론을 전제로 합니다. Qwen3 카드는 대부분의 질문에 출력 길이를 32k 토큰으로 잡으라고 권합니다. Qwen3.5·Qwen3.6 카드도 같고, 어려운 수학·프로그래밍 문제에는 80k까지 권합니다. DeepSeek은 R1 평가에서 생성 길이를 최대 32k 토큰으로 잡았습니다. 컨텍스트가 4k나 8k라면 긴 추론 도중에 가득 찰 수 있습니다.

작은 카드에서 Ollama를 쓰면 이런 일이 더 자주 생깁니다. <RuntimeFact id="ollama-default-ctx" />. 답을 쓰다 컨텍스트가 차면 Ollama는 앞부분을 밀어내고 계속 생성합니다. 그 결과 대화 앞부분이 빠집니다. 컨텍스트를 늘리는 방법은 ‘<GuideLink slug="ollama-context-length" />’ 가이드에 있습니다.

지난 턴의 추론은 부담이 덜합니다. Qwen3·Qwen3.6·Gemma 4 모델 카드는 대화 기록에 지난 턴의 최종 답만 남기라고 설명합니다. 이 모델들의 채팅 템플릿도 지난 추론을 지웁니다. 다만 Gemma 4는 도구 호출 턴의 추론은 남깁니다. 일부러 남기는 설정도 있습니다. Qwen3.6에는 `preserve_thinking` 옵션이 있습니다. llama-server의 `--reasoning-preserve`는 기본으로 켜져 있습니다. 이를 지원하는 템플릿이면 지난 추론도 기록에 남습니다.

## 이 숫자는 얼마나 확실한가

메모리 수치는 실제 GGUF 파일 크기와 파일 헤더, 모델 설정 파일(config)로 공식에 따라 계산한 값입니다. 그래서 오차 범위를 붙이지 않습니다. 속도는 추정치라서 오차 범위와 신뢰 라벨을 함께 붙입니다. ‘보정된 추정’의 오차 범위는 NVIDIA·AMD 카드에서 dense 모델을 GPU에만 올릴 때 ±12%입니다. MoE 모델이나 부분 오프로드, 그 밖의 하드웨어에서는 ±20%입니다. ‘이론 추정’은 ±30%로, MoE 전문가를 RAM에 두는 경우처럼 실제 속도 편차가 큰 구성에 붙입니다. 이 글의 판정표는 대부분 보정된 추정입니다. 16GB·24GB 카드의 gpt-oss-20b에는 ‘실측’ 라벨이 붙고, 전문가를 RAM에 둔 칸은 이론 추정입니다.

가장 불확실한 부분은 1.5배라는 배수입니다. CanRun이 잰 값이 아니라 정해 둔 정책이고, 생각에 드는 실제 비용은 질문마다 다릅니다. 판정은 사용자 설정이 아니라 모델을 기준으로 합니다. 생각 모드를 끄고 쓴다면, 칸의 속도 범위를 기준표의 일반 기준과 비교해 보세요. 생각 모드를 켜고 쓴다면 답을 받기까지의 시간은 모델이 얼마나 오래 생각하는지에 달려 있습니다. 이 시간은 속도 추정만으로는 알 수 없습니다.

## 자주 묻는 질문

### 생각 모드를 켜면 VRAM이 더 필요한가요?

모델 자체에 필요한 메모리는 늘지 않습니다. 가중치와 토큰당 KV 캐시는 생각 모드를 켜든 끄든 같습니다. Qwen3 14B는 8k에서 어느 쪽이든 <Num kind="needGB" model="qwen3-14b" />가 필요하고, RTX 3060 12GB 같은 12GB 카드에 들어갑니다<Expect model="qwen3-14b" gpu="rtx-3060-12gb" fits="true" />. 다만 생각 토큰이 컨텍스트를 빨리 채웁니다. 긴 추론을 담으려고 컨텍스트를 늘리면 KV 캐시가 커집니다. f16 캐시로 32k를 쓰면 Qwen3 14B는 <Num kind="needGB" model="qwen3-14b" ctx="32768" />가 필요합니다.

### 생각 모드 모델은 토큰을 만드는 속도도 느린가요?

아니요. 토큰당 속도는 모델 크기와 양자화, 카드의 메모리 대역폭으로 정해집니다. 생각 모드가 있는지와는 관계가 없습니다. RTX 3060 12GB에서 Qwen3 14B와 Phi-4는 추정 속도가 비슷합니다. 생각 모드 모델이 느리게 느껴지는 이유는 답 하나에 토큰을 더 많이 쓰고, 생각이 끝나야 답이 시작되기 때문입니다.

### gpt-oss는 think를 false로 해도 왜 계속 생각하나요?

gpt-oss에는 끄는 설정이 없습니다. 모델 카드가 제공하는 추론 강도는 low·medium·high이고, Ollama도 gpt-oss에는 이 세 값만 허용합니다. 대신 `--think=low`나 `"think": "low"`를 쓰세요. DeepSeek R1 distill 모델도 늘 생각합니다. 다른 모델이라면 `--hidethinking`이 아니라 `--think=false`를 썼는지 확인하세요. `--hidethinking`은 추론을 숨기기만 합니다. Qwen3.5·Qwen3.6은 Qwen3의 `/no_think` 태그를 지원하지 않으니 런타임 스위치를 쓰세요. Ollama 오류 메시지는 생각 모드를 제대로 쓰려면 Qwen3와 DeepSeek R1을 다시 받으라고 안내합니다. 예전에 받은 모델이라면 다시 받아 보세요.

### 생각 모드를 꺼야 하나요?

일상 대화나 간단한 질문이라면 끄고, 수학·코딩이나 여러 단계를 거쳐야 하는 문제라면 켜 두세요. Qwen3 모델 카드의 설명도 같습니다. 복잡한 추론과 수학, 코딩에는 생각 모드를, 일반 대화에는 비생각 모드를 권합니다. 켜 둔 채로 쓸 때는 앞에서 본 방법으로 엄격한 기준을 넘을 수 있습니다. 더 빠른 카드, 한 단계 낮은 양자화, MoE 모델입니다.

### 생각하는 길이를 제한할 수 있나요?

어느 정도는 됩니다. llama-server의 `--reasoning-budget N`은 추론이 N토큰에 이르면 끝냅니다. gpt-oss는 Ollama와 llama.cpp 모두에서 추론 강도를 low로 낮출 수 있습니다. HyperCLOVA X SEED Think 14B 모델 카드에는 메시지에 적어 넣는 대략적인 길이 제한이 나옵니다. Ollama 문서에 나온 `think` 값은 켜기·끄기와 모델이 정해 둔 단계뿐입니다. 문서에는 숫자는 지원하지 않는다고 적혀 있습니다.
