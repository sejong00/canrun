## Qwen3.6에서 Qwen3.8로 달라진 점

Qwen은 2026년 4월에 Qwen3.6 35B-A3B를 먼저 공개했고, 같은 달에 Qwen3.6 27B를 내놓았습니다. Qwen3.8 27B는 2026년 8월에 나왔습니다. Qwen의 GitHub 저장소는 세 모델을 Qwen3.5와 함께 하나의 오픈 모델 시리즈로 묶어 소개합니다. Qwen3.8 27B 모델 카드에도 Qwen3.5 구조를 바탕으로 만들었다고 적혀 있습니다.

<ModelFacts models="qwen3.6-27b,qwen3.8-27b,qwen3.6-35b-a3b" />

두 27B 모델은 설계가 같습니다. 두 설정 파일(config)에 적힌 구조 이름도, 층 배치도 같습니다. 층은 <Num kind="layers" model="qwen3.6-27b" />개입니다. 선형 어텐션(Gated DeltaNet) 층 셋 다음에 전체 어텐션 층 하나가 오는 묶음이 되풀이됩니다. 네 층에 한 층만 전체 어텐션을 쓰는 셈입니다. 파라미터는 둘 다 <Num kind="params" model="qwen3.8-27b" />이고, 모델이 지원하는 컨텍스트도 <Num kind="maxContext" model="qwen3.8-27b" />로 같습니다. Qwen은 일부 서빙 엔진에서 RoPE 스케일링(YaRN)으로 100만 토큰 안팎까지 늘릴 수 있다고 설명합니다. 두 모델 모두 Apache 2.0 라이선스이고, 이미지와 영상도 입력으로 받습니다.

무엇이 나아졌는지는 모델 카드의 설명으로 알 수 있습니다. 모델 카드에 따르면 Qwen3.6은 에이전트 코딩에 초점을 맞췄습니다. 지난 턴의 추론을 남겨 두는 옵션도 Qwen3.6이 내세운 기능입니다. Qwen3.8 카드는 코딩, 전문 업무, 리서치, 여러 단계를 거치는 긴 에이전트 작업이 두루 나아졌다고 설명합니다. Qwen3.8에는 추론 강도를 정하는 `reasoning_effort` 설정도 생겼습니다. 기본값인 `xhigh`와 `medium`, `low` 가운데 고릅니다. 지난 턴의 추론도 기본으로 남깁니다(`preserve_thinking`). Qwen3.6은 `preserve_thinking`을 켜야만 지난 추론을 남기고, 기본으로는 마지막 턴의 추론만 씁니다.

Qwen3.8 27B 모델 카드의 벤치마크 표에는 Qwen3.6 27B 열도 있습니다. 두 모델의 점수가 모두 적힌 항목에서는 전부 Qwen3.8의 점수가 높습니다. 다만 제작사가 직접 낸 수치라 이 글에는 옮기지 않습니다. CanRun은 답의 품질을 재지 않습니다. 그래서 이 글은 메모리와 속도만 비교합니다.

CanRun 데이터에서 두 27B가 다른 곳은 GGUF 파일입니다. 위 표의 GGUF 출처 열을 보면 Qwen3.6 27B는 unsloth 파일로 계산합니다. Qwen3.8 27B와 Qwen3.6 35B-A3B는 bartowski 파일로 계산합니다. 그래서 양자화 파일 구성도 조금 다릅니다. CanRun이 계산하는 2비트 파일은 Qwen3.6이 UD-Q2_K_XL, Qwen3.8이 Q2_K입니다.

Qwen3.8 35B-A3B는 없습니다. 2026년 10월에 Qwen의 Hugging Face 페이지를 확인했습니다. Qwen3.8로 공개된 모델은 27B와 그 FP8 판, 훨씬 큰 모델들뿐이었습니다. 큰 모델들은 CanRun이 계산하지 않습니다. 35B-A3B 가운데 가장 최근 모델은 Qwen3.6 35B-A3B입니다. Qwen3.7이라는 모델은 Hugging Face에 공개되지 않았습니다.

Qwen3.6 35B-A3B는 전체 파라미터가 약 35B이고, 토큰마다 쓰는 활성 파라미터는 약 3B입니다. 전문가는 256개이고, 토큰마다 라우팅 전문가 8개와 공유 전문가 1개를 씁니다. 층은 40개이고, 네 층에 한 층만 전체 어텐션을 쓰는 배치는 27B와 같습니다. Qwen3.6과 Qwen3.8에는 작은 모델이 없습니다. 아래 판정 표에 넣은 Qwen3.5 9B는 그보다 앞선 Qwen3.5 때 나온 모델입니다.

## 생각 모드 — 엄격한 속도 기준과 끄는 법

네 모델 모두 생각 모드가 기본으로 켜져 있어서, CanRun은 속도 기준을 1.5배 엄격하게 적용합니다. 생각 모드를 꺼도 판정은 바뀌지 않습니다. 판정은 사용자 설정이 아니라 모델을 기준으로 하기 때문입니다. Q2_K로 받은 Qwen3.8 27B가 좋은 예입니다. RTX 5060 Ti 16GB에서 GPU에 전부 올라가는데도 원활하게 돌아갑니다<Expect model="qwen3.8-27b" gpu="rtx-5060-ti-16gb" quant="Q2_K" verdict="A" mode="full-gpu" />. 추정 속도가 일반 쾌적 기준은 넘지만, 엄격한 기준에는 못 미치기 때문입니다.

Ollama에서는 `ollama run qwen3.8:27b --think=false`로 끄거나, 대화 중에 `/set nothink`를 입력합니다. API로는 `"think": false`를 보냅니다. OpenAI 호환 `/v1` 엔드포인트에는 `"reasoning_effort": "none"`을 보냅니다. llama-server는 `--reasoning off`(`-rea off`)로 띄웁니다. 요청마다 끄려면 `"chat_template_kwargs": {"enable_thinking": false}`를 보냅니다. 두 모델 카드도 이 방법을 안내합니다. Qwen3.6 카드에 따르면 Qwen3의 `/think`·`/nothink` 태그는 공식 지원하지 않습니다.

Qwen3.8의 채팅 템플릿은 `reasoning_effort` 값으로 `xhigh`(기본값)·`medium`·`low`만 받습니다. 다른 값을 주면 오류가 납니다. llama-server에서는 `--reasoning-effort low`처럼 주면 이 값이 템플릿으로 넘어갑니다. Qwen3.6 템플릿에는 강도 단계가 없습니다.

Qwen3.8은 지난 턴의 생각을 기본으로 남기고(`preserve_thinking`), Qwen3.6은 켜야만 남깁니다. 런타임이 지난 생각을 다시 보낸다면 그 생각도 다른 대화 내용처럼 컨텍스트를 차지합니다. 그러면 대화가 길어질수록 컨텍스트가 더 빨리 찹니다. 생각 모드 전반은 ‘<GuideLink slug="thinking-models" />’ 가이드에서 다룹니다.

## Ollama 태그와 llama.cpp 명령

Ollama의 `qwen3.6`(`qwen3.6:latest`)은 35B-A3B입니다. `qwen3.6:35b-a3b`와 같은 파일이고, dense 모델은 `qwen3.6:27b`입니다. 그래서 `ollama run qwen3.6`으로는 27B가 아니라 35B-A3B를 받습니다. `qwen3.8`(`latest`)은 `qwen3.8:27b`이고, qwen3.8에는 35B-A3B 태그가 없습니다. 기본 태그는 Q4_K_M이고 비전 프로젝터가 함께 들어 있습니다. 목록에는 q8_0, bf16, mtp 태그도 있습니다.

CanRun 계산으로는 16GB 카드에서 Q4_K_M인 Qwen3.8 27B가 일부를 RAM에 두고 겨우 돌아갑니다<Expect model="qwen3.8-27b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" />. 기본 태그도 Q4_K_M이지만, Ollama 라이브러리의 파일은 Ollama가 직접 만든 것이라 CanRun이 계산한 파일과 다릅니다. CanRun이 계산한 파일을 그대로 쓰려면 `hf.co/` 형식으로 받습니다.

```powershell
ollama run hf.co/bartowski/Qwen3.8-27B-GGUF:IQ4_XS
ollama run hf.co/unsloth/Qwen3.6-27B-GGUF:IQ4_XS
ollama run hf.co/bartowski/Qwen_Qwen3.6-35B-A3B-GGUF:Q4_K_M
```

컨텍스트를 정하려면 작업 표시줄에서 Ollama 앱을 먼저 종료합니다. 그다음 PowerShell에서 `$env:OLLAMA_CONTEXT_LENGTH="8192"; ollama serve`로 서버를 띄우고, 모델은 다른 창에서 실행합니다. macOS·Linux에서는 `OLLAMA_CONTEXT_LENGTH=8192 ollama serve`로 씁니다.

llama.cpp는 Windows에서 `.\llama-server.exe`, macOS·Linux에서 `llama-server`로 실행합니다. 아래는 CanRun이 RTX 5060 Ti 16GB에 맞춰 계산한 명령입니다.

```powershell
.\llama-server.exe -hf bartowski/Qwen3.8-27B-GGUF:Q4_K_M -c 8192 -ngl 52 -fa on
.\llama-server.exe -hf bartowski/Qwen_Qwen3.6-35B-A3B-GGUF:Q4_K_M -c 8192 -ngl all --n-cpu-moe 15 -fa on
```

두 번째 명령의 `-ngl all`은 모든 층을 GPU에 올리고, `--n-cpu-moe 15`는 앞쪽 15개 층의 전문가를 시스템 RAM에 둡니다. CanRun 계산으로는 35B-A3B가 이 카드에서 전문가 일부를 RAM에 두기 때문입니다<Expect model="qwen3.6-35b-a3b" gpu="rtx-5060-ti-16gb" fits="true" mode="cpu-moe" />. IQ4_XS라면 배치를 `--fit`에 맡깁니다. `.\llama-server.exe -hf bartowski/Qwen3.8-27B-GGUF:IQ4_XS -c 8192`로 실행하면 됩니다. 이미지 없이 글만 쓴다면 `--no-mmproj`를, 생각 모드를 끄려면 `--reasoning off`를 붙입니다.

런타임이 실제로 배치하는 방식은 CanRun 계산과 다를 수 있습니다. `ollama ps`의 PROCESSOR 열이나 llama.cpp 시작 로그에서 확인하세요. MoE 모델을 나눠 올리는 방식은 ‘<GuideLink slug="moe-cpu-offload" />’ 가이드에서 설명합니다.

## 이 숫자는 얼마나 확실한가

메모리는 GGUF 헤더를 읽어 공식으로 계산한 값이라 오차 범위를 붙이지 않습니다. MTP 블록과 비전 파일은 빼고 계산했고, 속도도 MTP를 끈 상태로 추정했습니다. 속도에는 신뢰 라벨이 붙습니다. ‘보정된 추정’은 NVIDIA 카드에서 dense 모델을 GPU에만 올리면 ±12%입니다. 부분 오프로드나 MoE 모델이면 ±20%입니다. ‘이론 추정’은 ±30%이고, 전문가를 시스템 RAM에 둔 구성에 붙습니다.

## 자주 묻는 질문

### Qwen3.8 27B가 Qwen3.6 27B보다 성능이 좋은가요?

모델 카드는 그렇다고 하지만, CanRun이 확인한 것은 아닙니다. Qwen3.8 27B 모델 카드는 두 모델의 점수가 모두 있는 벤치마크 항목에서 전부 Qwen3.8이 높다고 보고합니다. 제작사가 직접 낸 수치이고, CanRun은 답의 품질을 재지 않습니다. 메모리와 속도는 거의 같아서, RTX 3090에서는 둘 다 쾌적하게 돌아갑니다<Expect model="qwen3.6-27b" gpu="rtx-3090" verdict="S" /><Expect model="qwen3.8-27b" gpu="rtx-3090" verdict="S" />.

### Qwen3.8 27B는 Qwen3.6 27B보다 VRAM이 더 필요한가요?

거의 차이가 없습니다. 구조가 같고, 작은 차이는 GGUF 파일을 만든 곳이 달라서 생깁니다. 8k에서 Qwen3.6 27B는 <Num kind="needGB" model="qwen3.6-27b" />, Qwen3.8 27B는 <Num kind="needGB" model="qwen3.8-27b" />가 필요합니다. 그래서 RTX 5060 Ti 16GB에서는 둘 다 일부가 시스템 RAM에 남아 겨우 돌아갑니다<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" /><Expect model="qwen3.8-27b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" />.

### 16GB 그래픽카드로 Qwen3.6 27B나 35B-A3B를 돌릴 수 있나요?

둘 다 돌릴 수 있지만, 올라가는 방식이 다릅니다. RTX 5060 Ti 16GB로 계산하면 35B-A3B는 전문가 일부를 시스템 RAM에 두고 들어갑니다<Expect model="qwen3.6-35b-a3b" gpu="rtx-5060-ti-16gb" fits="true" mode="cpu-moe" />. 27B는 Q4_K_M이면 일부가 RAM에 남아 겨우 돌아갑니다<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" />. IQ4_XS로 받으면 원활하게 돌아갑니다<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" quant="IQ4_XS" verdict="A" />. 2비트 파일은 GPU에 전부 들어가지만<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" quant="UD-Q2_K_XL" fits="true" mode="full-gpu" />, 품질은 손실 큼 등급입니다.

### Qwen3.8 35B-A3B는 없나요?

없습니다. 2026년 10월에 확인한 Qwen의 Hugging Face 페이지에는 Qwen3.8 35B-A3B가 없었습니다. 그곳의 Qwen3.8 모델은 27B와 훨씬 큰 모델들입니다. 가장 최근의 35B-A3B는 Qwen3.6 것이고, RTX 3090에서는 GPU에 전부 올라가 쾌적하게 돌아갑니다<Expect model="qwen3.6-35b-a3b" gpu="rtx-3090" verdict="S" mode="full-gpu" />.

### Qwen3.6·Qwen3.8의 생각 모드는 어떻게 끄나요?

Ollama에서는 `--think=false`, llama-server에서는 `--reasoning off`로 끕니다. 요청마다 끄려면 `chat_template_kwargs`로 `enable_thinking: false`를 보냅니다. Qwen3.6 카드에 따르면 Qwen3의 `/think`·`/nothink` 태그는 공식 지원하지 않습니다. 생각 모드를 꺼도 CanRun 판정은 그대로입니다. 판정은 모델을 기준으로 하기 때문입니다.
