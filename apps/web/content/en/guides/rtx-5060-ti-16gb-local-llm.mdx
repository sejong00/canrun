## How we measured, so you can repeat it

The test is a PowerShell script in CanRun's repository, [scripts/own-bench/ollama-bench.ps1](https://github.com/sejong00/canrun/blob/main/scripts/own-bench/ollama-bench.ps1). It talks to a running Ollama through its local API and does the following for each model:

- loads the model and sends one warm-up request, which it throws away;
- sends three requests with the same long prompt, changing the first line every time so that Ollama cannot reuse the processed prompt from its cache;
- uses an 8k context window (`num_ctx 8192`), at most 256 new tokens (`num_predict 256`), temperature 0, and thinking turned off for models that have it;
- reads the generation speed as `eval_count` divided by `eval_duration`, and the prompt speed as `prompt_eval_count` divided by `prompt_eval_duration`, the timings Ollama returns with every reply;
- records how much of the model sat in VRAM, because a model that spills into system RAM runs far slower;
- unloads the model before moving on to the next one.

To run it on your own PC, start Ollama, then open PowerShell:

```powershell
git clone https://github.com/sejong00/canrun
cd canrun
powershell -ExecutionPolicy Bypass -File scripts\own-bench\ollama-bench.ps1 -Models llama3.1:8b,gemma3:12b -Pull -RemoveAfter
```

`-Pull` downloads models you do not have yet, and `-RemoveAfter` deletes only the models the script downloaded once they have been measured. Without `-Models` the script measures every model you already have. Results go to a new folder under `data\own-bench\raw`, with one line per run in `results.json`, the same rows in `summary.csv`, and the card, CPU, RAM size and Ollama version in `system.json`. The script records names and sizes only, not your user name or file paths.

The raw results of the runs on this page are in the repository as well: [results.json](https://github.com/sejong00/canrun/blob/main/data/own-bench/raw/20261025-131211/results.json) and [system.json](https://github.com/sejong00/canrun/blob/main/data/own-bench/raw/20261025-131211/system.json).

## Why the runs were faster than CanRun's estimate

The gap has two parts, and only one of them is a mistake.

The first part is the context. CanRun rates every model at an 8k context, and as a chat grows each new token has to read more of the KV cache. These runs stopped at about 650 tokens. CanRun's own formula says that at that depth Llama 3.1 8B would generate about a fifth faster than at 8k, Qwen3 8B a little more and Gemma 3 12B much less, because Gemma 3 keeps most of its layers to a short sliding window. The same formula has matched public benchmarks of this card at 4k and 16k well: the drop it predicts between the two is close to what was measured. So part of the gap is simply that a short chat is faster than a full one.

The second part is the efficiency figure. Even when we put the real depth and the exact file size into the formula, CanRun's estimate came out 15% below the Gemma 3 12B run and 23–24% below the other three. That is outside the ±12% range CanRun gives a calibrated estimate on an NVIDIA card. CanRun uses one efficiency figure for every NVIDIA card. In the public results it was fitted to, cards with less bandwidth already came closer to their rated bandwidth than fast cards such as the RTX 4090, and the RTX 5060 Ti 16GB is one of the slower ones. A public llama-bench result for this card from an August 2025 llama.cpp build was already above CanRun's estimate, though still inside the range. These runs, on a much newer Ollama, are further above it.

We cannot yet tell how much of that second part comes from the card itself and how much from the newer software. Ollama and llama-bench also time things a little differently. Separating them needs a llama-bench run with a current llama.cpp build on the same PC, which is first on our list below. Until then CanRun keeps its estimate as it is. We have not changed the calculation to match one machine, and whether to refit the figure for this card is a decision we will record on the methodology page if we make it.

## What we will measure next

- **llama-bench on the same PC** with a current llama.cpp build, using `-d 0,8192`, so that one run gives both an empty context and the 8k depth CanRun rates at. This separates the effect of the newer software from the card, and checks the 8k figure directly.
- **Qwen3 8B and Qwen3 14B with CanRun's files.** Ollama can pull a GGUF straight from Hugging Face, for example `ollama pull hf.co/unsloth/Qwen3-8B-GGUF:Q4_K_M`, which is the file CanRun lists. Those runs can then join the catalog like the two above.
- **gpt-oss-20b**, to see whether our machine reproduces the public result shown on its page.
- **An MoE model with experts in system RAM**, such as Qwen3 30B-A3B, because those estimates carry the theoretical label and need real measurements most.
- **Korean models** such as Kanana 1.5 8B, which have few public benchmarks anywhere.

## How sure are these numbers?

The measured label means a benchmark of the same card, model and quant exists, here one we ran ourselves and published with its raw log. It is still one machine. Another RTX 5060 Ti 16GB with a different driver, a factory overclock, other programs using the GPU or a longer conversation will land somewhere else, and a full 8k chat will be slower than these runs. The three runs per model were within about one percent of each other, so repeating the test on the same PC changes little; the conditions above matter more.

For cells without a measurement, CanRun's speeds are estimates with a range and a label. Calibrated means ±12% for dense models fully on an NVIDIA or AMD card and ±20% for other setups; theoretical means ±30%. On this card, our runs suggest the calibrated range sits low for short chats. ## FAQ

### Why was Ollama faster than CanRun's estimate?

Mostly because of the context and the efficiency figure. These runs had a short prompt, while CanRun rates at a full 8k context, which is slower. At the same depth CanRun's estimate was still 15–24% low for this card, outside its calibrated range, which points at the single efficiency figure CanRun uses for all NVIDIA cards and possibly at newer software.

### Is Ollama's Q4_K_M the same file as the one on Hugging Face?

Not always. Ollama's Llama 3.1 8B and Gemma 3 12B match the Hugging Face files CanRun lists tensor by tensor, but its Qwen3 8B and Qwen3 14B keep the `attn_v` weights at 16-bit and are a few percent larger. If you compare your speed with a site like CanRun, check which file you have: `ollama show <model>` names the quant, and pulling with `hf.co/<repository>:<quant>` gets the exact Hugging Face file.

### Why does the result say 512 context when the script sets 8192?

`num_ctx 8192` only sets how much memory Ollama reserves for the context. Speed depends on how much of it is filled, and these runs filled under a thousand tokens. CanRun records short-prompt results the way it records llama-bench's short test, under 512.

### Can I send my own measurement?

Yes. Run the script, then send the `summary.csv` and `system.json` it writes through the contact page, or open an issue on the GitHub repository. Tell us whether anything else was using the GPU. We add a result to a page only when the file matches the one CanRun lists.
