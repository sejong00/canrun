## What changed from Qwen3.6 to Qwen3.8

Qwen released Qwen3.6 35B-A3B in April 2026 and Qwen3.6 27B later that month, then Qwen3.8 27B in August 2026. Qwen's GitHub repository groups all three in one open-model series with Qwen3.5, and the Qwen3.8 card says the model is built on the Qwen3.5 architecture.

<ModelFacts models="qwen3.6-27b,qwen3.8-27b,qwen3.6-35b-a3b" />

The two 27Bs share one design. Their configuration files declare the same architecture type and the same <Num kind="layers" model="qwen3.6-27b" /> layers, where three linear-attention (Gated DeltaNet) layers are followed by one full-attention layer, so one layer in four uses full attention. Both have <Num kind="params" model="qwen3.8-27b" /> parameters and a native context of <Num kind="maxContext" model="qwen3.8-27b" /> tokens, which Qwen says some serving engines can stretch to about a million with RoPE scaling (YaRN). Both are released under Apache 2.0 and take image and video input.

According to Qwen, what changed is the focus and the thinking controls. Qwen describes Qwen3.6 as aimed at agentic coding, with an option to keep earlier turns' reasoning. For Qwen3.8 it claims broad gains in coding, professional work, research and long multi-step agent tasks. Qwen3.8 also adds a `reasoning_effort` setting (`xhigh` by default, `medium` or `low`) and keeps earlier turns' reasoning by default (`preserve_thinking`). Qwen3.6 keeps only the latest turn's reasoning unless you turn `preserve_thinking` on.

The Qwen3.8 27B card puts Qwen3.6 27B in its benchmark tables and reports a higher score for 3.8 on every row that lists both. Those are Qwen's own figures. CanRun does not measure answer quality, so this guide compares memory and speed only.

In CanRun's data, the two 27Bs differ in their GGUF files, as the GGUF source column shows. Qwen3.6 27B is calculated from unsloth's files, while Qwen3.8 27B and Qwen3.6 35B-A3B are calculated from bartowski's. So the quant sets differ: the 2-bit file is UD-Q2_K_XL for Qwen3.6 and Q2_K for Qwen3.8.

There is no Qwen3.8 35B-A3B. Qwen's Hugging Face page, checked in October 2026, lists for Qwen3.8 only the 27B (plus an FP8 version) and much larger models that CanRun does not calculate, and it lists no Qwen3.7 model. The newest 35B-A3B is therefore Qwen3.6's. It has about 35B parameters in total, and each token uses 8 of its 256 routed experts plus 1 shared expert, about 3B parameters in all. Its 40 layers follow the same one-in-four full-attention pattern. Neither newer version has a small model, so the grid's smallest model, Qwen3.5 9B, comes from the Qwen3.5 release.

## Thinking mode: the stricter bar and how to turn it off

All four models think by default, so CanRun holds them to 1.5× stricter speed thresholds, because a thinking reply costs many more tokens. The verdict follows the model, so turning thinking off does not change it. The 2-bit Qwen3.8 27B on the RTX 5060 Ti 16GB shows the bar: it sits fully on the GPU and still Runs well, because its estimate clears the normal Runs great line but not the stricter one.<Expect model="qwen3.8-27b" gpu="rtx-5060-ti-16gb" quant="Q2_K" verdict="A" mode="full-gpu" />

To turn thinking off in Ollama, run `ollama run qwen3.8:27b --think=false`, or type `/set nothink` inside a session. Through Ollama's API, send `"think": false`; on its OpenAI-compatible `/v1` endpoint, send `"reasoning_effort": "none"`. In llama-server, start with `--reasoning off` (`-rea off`), or send `"chat_template_kwargs": {"enable_thinking": false}` with a request, the form both model cards show. The Qwen3.6 card says Qwen3's `/think` and `/nothink` tags are not officially supported.

Qwen3.8's chat template accepts a `reasoning_effort` of `xhigh` (the default), `medium` or `low`, and raises an error for any other value. llama-server's `--reasoning-effort low` passes the level to the template. Qwen3.6's template has no levels.

Qwen3.8 also keeps earlier turns' thinking by default, while Qwen3.6 keeps only the latest turn's unless you turn `preserve_thinking` on. If your runtime sends that thinking back with the chat history, it takes up context like any other text, so a long chat fills the context sooner. <GuideLink slug="thinking-models" /> covers the speed cost in more detail.

## How sure are these numbers?

Memory is calculated by formula from the GGUF headers, so it carries no error band. MTP blocks and vision files are left out, and the speed estimates assume MTP is off. Calibrated speeds are ±12% for a dense model fully on an NVIDIA card, and ±20% for an MoE model or partial offload. Theoretical speeds are ±30%, used here when experts sit in system RAM.

## FAQ

### Is Qwen3.8 27B better than Qwen3.6 27B?

Qwen's own benchmarks say so, but CanRun does not measure answer quality. The Qwen3.8 27B card reports a higher score for 3.8 on every benchmark row that lists both models, and those are the maker's own figures. In memory and speed the two are nearly the same. Both Run great on the RTX 3090.<Expect model="qwen3.6-27b" gpu="rtx-3090" verdict="S" /><Expect model="qwen3.8-27b" gpu="rtx-3090" verdict="S" />

### Does Qwen3.8 27B need more VRAM than Qwen3.6 27B?

Almost no more, and the small gap does not come from the model. The two share one architecture, and their GGUF files come from different publishers: at 8k, Qwen3.6 27B needs <Num kind="needGB" model="qwen3.6-27b" /> and Qwen3.8 27B needs <Num kind="needGB" model="qwen3.8-27b" />. At Q4_K_M both Run slowly on the RTX 5060 Ti 16GB, with part of the model in system RAM.<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" /><Expect model="qwen3.8-27b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" />

### Can a 16GB GPU run Qwen3.6 27B or Qwen3.6 35B-A3B?

On the RTX 5060 Ti 16GB, both run, in different ways. The 35B-A3B fits with part of its experts in system RAM.<Expect model="qwen3.6-35b-a3b" gpu="rtx-5060-ti-16gb" fits="true" mode="cpu-moe" /> The 27B at Q4_K_M Runs slowly with part of the model in system RAM,<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" /> and IQ4_XS brings it up to Runs well.<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" quant="IQ4_XS" verdict="A" /> The 2-bit UD-Q2_K_XL file fits fully on the GPU,<Expect model="qwen3.6-27b" gpu="rtx-5060-ti-16gb" quant="UD-Q2_K_XL" fits="true" mode="full-gpu" /> but it is in the Heavy loss group.

### Is there a Qwen3.8 35B-A3B?

No. As of October 2026, Qwen's Hugging Face page lists none. The Qwen3.8 models there are the 27B and much larger models, so the newest 35B-A3B is Qwen3.6's, which Runs great fully on the RTX 3090.<Expect model="qwen3.6-35b-a3b" gpu="rtx-3090" verdict="S" mode="full-gpu" />

### How do I turn off thinking in Qwen3.6 and Qwen3.8?

Use `--think=false` in Ollama, `--reasoning off` in llama-server, or `"enable_thinking": false` inside `chat_template_kwargs` in an API request. The Qwen3.6 card says Qwen3's `/think` and `/nothink` tags are not officially supported. CanRun's verdict stays the same with thinking off, because it follows the model.
