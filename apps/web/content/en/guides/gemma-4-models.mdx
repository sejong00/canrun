## Three sizes, two designs

Besides two small edge models, Gemma 4 comes in three sizes for desktop graphics cards, built in two ways. The 12B and the 31B are dense models: every token passes through every weight. The 26B-A4B is a mixture-of-experts (MoE) model. According to its model card and configuration file, each layer holds 128 experts, small blocks of weights, and a router picks 8 of them per token, plus one shared expert. That makes about 26B parameters in total and about 4B active per token, hence the name.

<ModelFacts models="gemma-4-12b,gemma-4-26b-a4b,gemma-4-31b" />

Google released the 26B-A4B and the 31B in April 2026, together with the two edge models, E2B and E4B. The 12B followed in June 2026. Its model card lists it as "12B Unified", a dense model without separate image or audio encoders that takes text, image and audio input. The other two take text and images. All three have a 256k context and the Apache 2.0 license. Their configuration files give 48 layers for the 12B, 30 for the 26B-A4B and 60 for the 31B.

Google's model card says the 26B-A4B runs almost as fast as a 4B-parameter model, and the 12B release post says the 12B is small enough for 16GB of VRAM or unified memory. In CanRun's calculation, the 12B at Q4_K_M fits fully even on a 12GB card.<Expect model="gemma-4-12b" gpu="rtx-3060-12gb" fits="true" mode="full-gpu" /> The edge models come up again in the section on Ollama's tags.

## Ollama's gemma4 tags and the files CanRun calculates

On Ollama's library page (checked October 2026), `ollama run gemma4` pulls `gemma4:latest`, which is the same build as `gemma4:e4b`. ## Thinking mode: off in the model, on by default in Ollama

All three sizes have a thinking mode. According to the model card, it is on only when the system prompt starts with the `<|think|>` token, and the chat template sets `enable_thinking` to false by default. CanRun therefore records Gemma 4 as a model with thinking off by default.

CanRun still holds Gemma 4 to the 1.5× stricter speed thresholds for thinking models, which the legend does not show. The reason is the runtimes. Ollama's local default keeps thinking on for models that can switch it, and its own tests include the case "local gemma default on". llama-server's `--reasoning` option defaults to `auto`, which turns thinking on when the chat template supports it.

With thinking off, a Gemma 4 cell can be one grade better than the grid shows. The 12B IQ4_XS file on the RTX 4060 is an example: it is fully on the GPU, yet it Runs well,<Expect model="gemma-4-12b" gpu="rtx-4060" quant="IQ4_XS" verdict="A" mode="full-gpu" /> because its estimate sits just under the stricter Runs great line.

To turn thinking off, run `ollama run gemma4:26b --think=false` in Ollama, or start llama-server with `--reasoning off`. According to the model card, the 12B, 26B and 31B still print an empty thought block when thinking is off. For the speed cost of thinking, see <GuideLink slug="thinking-models" />.

## How sure are these numbers?

Memory figures come by formula from the real GGUF file sizes, each model's configuration file, and the expert and non-expert sizes in the GGUF headers. Whether a model fits is a calculation, not an estimate.

Speeds are estimates with a band and a label. Measured means a public benchmark for that card, model and quant: here, the 26B-A4B on the RTX 3090 and the RTX 5090, and the 12B on the Radeon RX 9060 XT 16GB. The RTX 3090 run used Ollama's own build of the Q4_K_M quant. Calibrated means ±12% for dense models fully on an NVIDIA or AMD card, such as the 12B and the 31B, and ±20% for MoE models fully on the GPU and for partial offload. Theoretical means ±30%, used when experts sit in system RAM.

All verdicts assume Windows with the card driving the display, 32GB of DDR5-5600 dual-channel system RAM, an 8k context, an f16 KV cache, one model and one request at a time. Ollama and llama.cpp estimate memory their own way, so check `ollama ps` when a model fits with little margin.

The 26B-A4B is an MoE model that uses about 4B of its parameters per token, while the 31B is dense; at Q4_K_M, both need 24GB to sit fully on the GPU.<Expect model="gemma-4-26b-a4b" gpu="rtx-3090" fits="true" mode="full-gpu" /><Expect model="gemma-4-31b" gpu="rtx-3090" fits="true" mode="full-gpu" /> On the 16GB RTX 5060 Ti, the 31B Runs slowly,<Expect model="gemma-4-31b" gpu="rtx-5060-ti-16gb" verdict="B" mode="partial-offload" confidence="calibrated" /> while the 26B-A4B's IQ4_XS file fits fully and Runs great.<Expect model="gemma-4-26b-a4b" gpu="rtx-5060-ti-16gb" quant="IQ4_XS" verdict="S" mode="full-gpu" /> On the RTX 3090 both Run great, and a public benchmark backs the 26B-A4B result.<Expect model="gemma-4-26b-a4b" gpu="rtx-3090" verdict="S" confidence="measured" /><Expect model="gemma-4-31b" gpu="rtx-3090" verdict="S" />

### Can Gemma 4 26B-A4B run with only 16GB of system RAM?

In CanRun's calculation, yes, even on the 8GB RTX 4060, by keeping most of its experts in system RAM.<Expect model="gemma-4-26b-a4b" gpu="rtx-4060" ram="16" fits="true" mode="cpu-moe" /> The dense 31B does not fit on that card with 16GB of RAM.<Expect model="gemma-4-31b" gpu="rtx-4060" ram="16" fits="false" /> Speed with experts in system RAM is a theoretical estimate; the grid above shows its band on each card with 32GB of RAM. After loading, check the split with `ollama ps`.

### Which model does `ollama run gemma4` download?

The E4B edge model: the default `gemma4:latest` is the same build as `gemma4:e4b` (checked October 2026). CanRun does not calculate E4B yet. For the sizes in this guide, use `gemma4:12b`, `gemma4:26b` or `gemma4:31b`, or the `hf.co` commands above for the exact files CanRun calculates.

### Does Gemma 4 think before it answers?

It can, but only when the system prompt starts with `<|think|>`; otherwise the model keeps thinking off. Ollama and llama-server switch it on by default, so CanRun uses the stricter thresholds for thinking models. To turn it off, add `--think=false` to `ollama run`, or start llama-server with `--reasoning off`.
