## ROCm, Vulkan and SYCL: what runs on Windows and Linux

Ollama and LM Studio both run GGUF models through llama.cpp, and llama.cpp reaches AMD and Intel cards mainly through three backends. ROCm is AMD's compute platform, which llama.cpp uses through its HIP backend. Vulkan is a graphics and compute API that works across vendors; Ollama's documentation notes that most Windows graphics drivers already include it. SYCL is the backend llama.cpp's documentation describes as designed primarily for Intel GPUs. The weights and KV cache are the same size whichever backend runs them, so CanRun's memory figures do not change. The runtime's own working memory can differ a little by backend, so near the limit, check `ollama ps`.

### Ollama

Ollama's hardware page lists two sets of Radeon cards for ROCm (checked October 2026):

- **Linux**, with AMD's ROCm v7 driver: the RX 9070 XT, 9070 GRE, 9070, 9060 XT, 9060 XT LP and 9060, the RX 7000 cards from the 7600 up, the RX 6800 and faster RX 6000 cards, plus Radeon PRO and Ryzen AI chips.
- **Windows**, with a driver that supports ROCm v7 (HIP 7): only the RX 7900 XTX, 7900 XT, 7900 GRE, 7800 XT, 7700 XT, 7600 XT and 7600, plus the Radeon PRO W7500 to W7900.

For other GPUs Ollama uses Vulkan, which the same page says is enabled by default once its backend is installed, on Windows and Linux. So on Windows, Ollama runs the <HubLink gpu="rx-9070-xt" /> and the <HubLink gpu="rx-9060-xt-16gb" /> through Vulkan. The page does not name Intel Arc cards; they fall under the same Vulkan support, and for Linux the page links Intel's driver instructions.

To see what Ollama picked, look for the `inference compute` line in its server log, which names the library (ROCm, Vulkan or CUDA) for each GPU it found. For where the log lives and what to try when the card is not found, see <GuideLink slug="gpu-offload-check" />.

### llama.cpp

Each llama.cpp release on GitHub carries separate Windows builds for Vulkan, ROCm and SYCL, next to the CUDA, CPU and other builds (checked on release b11630, October 2026). The Windows ROCm build covers more Radeon generations than Ollama's Windows list. Its release workflow targets RDNA 2 (RX 6000), RDNA 3 and RDNA 4 chips, including `gfx1030` and `gfx1031`, which LLVM's processor table maps to the RX 6800 to RX 6900 XT and to the RX 6700 XT, and `gfx1200` and `gfx1201`, the RX 9060 and RX 9070 families. Ollama runs RX 6000 and RX 9000 cards through Vulkan on Windows, so llama.cpp's ROCm build is the other option for them, though in llama.cpp's public results Vulkan generated faster on the RX 9070 XT (see "Which backend is faster?" below).

For Intel, llama.cpp's SYCL page lists the Arc B580 among its verified devices and Windows 11 as supported. Its Windows package includes the oneAPI libraries it depends on; you install Intel's GPU driver yourself. The releases also carry an OpenVINO build for Intel hardware, a backend llama.cpp's README lists as in progress.

Unzip a build, open PowerShell in that folder, and check which devices the build can see before you load a model. The second line is the command our combo pages print for gpt-oss-20b on a 16GB card. On Linux, run `./llama-server` from that folder instead.

```powershell
.\llama-server.exe --list-devices
.\llama-server.exe -hf ggml-org/gpt-oss-20b-GGUF:MXFP4 -c 8192 -ngl all -fa on
```

If `--list-devices` shows no GPU, that build cannot use your card; try the Vulkan build instead. If it lists more than one device, for example Radeon graphics built into the processor as well as your card, add `-dev` with your card's name from that list (such as `-dev Vulkan1`).

### LM Studio

LM Studio ships its llama.cpp engine as separate runtimes for the CPU, CUDA, Vulkan, ROCm and Metal. Press Ctrl+Shift+R to open the runtimes tab, then pick the Vulkan or ROCm runtime for a Radeon card, or the Vulkan runtime for an Arc card.

### Which backend is faster?

CanRun does not model the backend; its dense-model efficiency figures for Radeon and Arc cards come from public llama-bench results run through Vulkan. llama.cpp's own scoreboards give a rough answer for Llama 2 7B: on the RX 9070 XT, Vulkan generated about 30% faster than ROCm, and on the RX 7900 XTX about a tenth faster, while prompt speed was about the same on both cards. The B580's weaker side is reading the prompt. ## Why prompt processing lags on Radeon and Arc

Generation reads memory one token at a time. Prompt processing reads the whole prompt in large batches, so the GPU's compute sets its pace instead (see <GuideLink slug="tokens-per-second" />). It matters most when the model reads a lot before it answers: a pasted document, a chat whose cache was cleared, or the instructions and tool definitions of a coding agent.

CanRun's combo pages show a rough prompt speed (±40%) when the whole model is on the GPU, calculated from the card's FP16 compute. For AMD and Intel cards the calculation assumes about a quarter of the prompt speed per unit of compute that it assumes for NVIDIA cards, a figure based on public Vulkan results and set a little above the RX 7900 XTX's. In that rough estimate the RX 9070 XT reads prompts at a little over half the RTX 5070 Ti's speed, while it generates at about four-fifths.

Public results land on both sides of that figure: above it for the RX 9070 XT on Vulkan and for gpt-oss-20b on the RX 7900 XT through ROCm, below it for the RX 7900 XTX and the Arc B580. So treat the prompt figures on Radeon and Arc pages as a rough range. If long prompts matter to you, measure: `ollama run` with `--verbose` prints a `prompt eval rate`, and llama-server prints a `prompt eval time` line after each reply.

## How sure are these numbers?

The memory figures are calculated by formula from real GGUF file sizes and headers and each model's published configuration. They are the same for every brand, so the fit results in this guide apply to Radeon and Arc cards exactly as to NVIDIA cards.

The speeds are estimates with a band and a label. Measured means a public benchmark for that card, model and quant. Calibrated means ±12% for dense models fully on an NVIDIA or AMD card and ±20% for MoE models, partial offload and other hardware, Intel Arc included. Theoretical means ±30%; in this guide it covers MoE experts in system RAM and every MoE model on the Arc B580.

The Radeon and Arc dense-model efficiency figures rest on public Vulkan results for Llama 2 7B, which is not in the catalog, and no Radeon or Arc cell in the grid is measured. For MoE models, llama.cpp's gpt-oss guide thread has two ROCm results for gpt-oss-20b (llama-bench at a 2k context; not CanRun runs). An RX 7900 GRE, which is not in our catalog, ran the same MXFP4 file CanRun uses, and CanRun's formula puts that card about a tenth faster than it measured. ### Does Ollama use ROCm for Radeon RX 9000 cards on Windows?

On Windows, Ollama runs RX 9000 cards such as the RX 9070 XT and RX 9060 XT through Vulkan, which is on by default; on Linux, they are on its ROCm list. llama.cpp's own Windows ROCm build does target RX 9000 chips.

### Should I use ROCm or Vulkan?

Start with whatever your tool supports for your card, then measure if speed matters. In llama.cpp's public Llama 2 7B results, Vulkan generated faster than ROCm on the RX 9070 XT and the RX 7900 XTX, with about the same prompt speed. Ollama picks the backend for you; llama.cpp and LM Studio let you choose the build. CanRun's estimates are the same for both, so compare on your own card: load the same GGUF with each build and compare the speeds it prints. On Arc, add the SYCL build if your prompts are long.
